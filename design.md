Birthday Gift Game
1. Цель
Сделать небольшую полностью клиентскую веб-игру ко дню рождения.
Пользователь попадает на пиксельную сцену с нарциссами и развилкой к трём неизвестным подаркам.
Каждый подарок содержит:
• интерактивный объект на основной карте;
• только звуковую подсказку при hover;
• собственную мини-игру;
• сертификат на соответствующий подарок.
Три возможных подарка:
1. Щенок
2. Поездка в Армению
3. Поездка в Японию
На основном экране нельзя визуально понять, какой подарок где находится.
После получения сертификата пользователь может либо оставить выбранный подарок, либо вернуться на развилку и попробовать другой вариант.
Приложение должно быть коротким, абсурдным, милым и ощущаться как маленькая законченная игра.

Общие технические ограничения
Platform
• Static frontend only.
• Hosting: GitHub Pages.
• No backend.
• No authentication.
• No database.
• Desktop-only experience.
• Основная целевая платформа — современный desktop Chrome / Chromium.
• Основной стек:  
 • Vite
• React
• TypeScript
• обычный CSS
• Howler.js или Web Audio API
• Canvas только там, где он действительно упрощает механику.
Mobile fallback
На мобильных устройствах игра не запускается.
Показывать отдельный экран:
Oops!

Эта штука работает только на компьютере.

Открой ссылку на ноутбуке 💻
Не требуется поддерживать touch controls или mobile gameplay.

MVP asset strategy
Первую полностью играбельную версию сделать без рисования собственных спрайтов.
Для MVP использовать:
• emoji;
• простые CSS shapes;
• текст;
• CSS backgrounds;
• при необходимости простые SVG.
Примеры:
🐶 💩 🧺
🌸 🍣 🍙 🗻 ✈️
🥩 🍅 🧅 🫓
🎁 🌼
Архитектура должна позволять позже заменить emoji на PNG/WebP/SVG sprites без переписывания игровой логики.
Не привязывать игровую механику напрямую к конкретному виду ассета.
Предпочтительно иметь простой слой представления:
const assets = {
  puppy: "🐶",
  poop: "💩",
  gift: "🎁",
  sakura: "🌸",
  sushi: "🍣",
};
Позже значения могут быть заменены на пути к изображениям или отдельные React-компоненты.
Главный приоритет MVP — законченная механика от начала до финального сертификата.
Pixel-art polish выполняется только после того, как все три игры работают.
 
⸻
 
Navigation
Не использовать router без необходимости.
Приложение представляет собой конечный набор экранов:
type Screen =
  | "intro"
  | "map"
  | "puppy-game"
  | "armenia-game"
  | "japan-game"
  | "certificate"
  | "final";
Верхнеуровневое состояние:
type Gift = "puppy" | "armenia" | "japan";

interface GameState {
  screen: Screen;
  selectedGift: Gift | null;
  completedGames: Gift[];
}
Состояние не обязано переживать refresh.

Этап 1. Экран с нарциссами
Цель
Создать центральный экран выбора подарка.
Scene
Полноэкранное поле с нарциссами.
Для MVP сцену можно сделать CSS-фоном с множеством emoji 🌼 / 🌷 или повторяющимся паттерном.
В центре — дорожка, которая приходит снизу и разделяется на три направления.
Примерная композиция:
          🎁

     🎁         🎁

          |
          |
        START
Конкретная геометрия может быть органичной.
Главное правило
Все три конечные точки визуально выглядят одинаково.
Например:
🎁
или одинаковая закрытая коробка.
На основном экране не должно быть:
• щенка;
• флага Армении;
• Арарата;
• torii;
• Fuji;
• самолёта;
• текста с названием подарка;
• других визуальных подсказок.
Игрок должен выбирать только по звуку или вслепую.
Sound hints
Единственная подсказка — звук при наведении мыши.
Gift A
Короткий лай собаки.
Gift B
Короткий звук дудука / армянский музыкальный фрагмент.
Gift C
Японский railway / arcade / gacha-style sound.
Не показывать подписи.
Не показывать tooltip.
Не менять emoji подарка в зависимости от варианта.
Допустима небольшая одинаковая hover-анимация для всех подарков:
• bounce;
• scale;
• shake;
• glow.
Она не должна выдавать содержимое.
Click
После клика подарок раскрывается только переходом в соответствующую мини-игру:
Gift A → Puppy Game
Gift B → Armenia Game
Gift C → Japan Game
Соответствие между положением коробок и подарками фиксированное.
Completed state
После прохождения игры можно отметить конкретную коробку нейтральным способом:
🎁 → ✅
или добавить маленькую звёздочку.
При этом не раскрывать содержимое этой коробки на карте.

🧺

Этап 4. Mini-game 3 — Japan Gacha
Concept
Gacha machine из двух фаз.
Для MVP аппарат можно сделать из обычных HTML/CSS элементов и emoji.
Сложный sprite gacha machine не нужен.
Phase 1 — обычные rolls
Игрок получает 5 начальных rolls.
Каждый roll:
1. нажимает кнопку;
2. machine трясётся;
3. появляется capsule;
4. capsule открывается;
5. выпадает случайный collectible.
MVP pool:
🌸 sakura
🍣 sushi
🍙 onigiri
🗻 Fuji
🍜 ramen
🚅 Shinkansen
🐱 maneki-neko
🏮 lantern
🐟 koi
Duplicates разрешены.
Выпавшие предметы остаются снизу экрана как collection.
Phase 2 — special gacha
После пяти обычных rolls:
SUPER RARE CHANCE
Machine визуально начинает мигать / трястись сильнее.
Создаётся marble bag из пяти элементов.
В нём:
4 × обычный collectible
1 × ✈️
Rolls вытаскиваются без возвращения.
Самолёт должен выпасть гарантированно.
Для pacing его позиция выбирается только из:
3
4
5
То есть первые два special rolls гарантированно не дают самолёт.
Plane reveal
При выпадении:

самолёт вылетает из capsule и пролетает через экран.
Появляется:

Asset architecture
Важно разделить:
1. game logic;
2. visual representation.
Игровой код не должен зависеть от того, используется ли emoji или sprite.
Например, вместо прямого использования emoji по всему приложению:
const gameAssets = {
  puppy: "🐶",
  poop: "💩",
  basket: "🧺",
  gift: "🎁",
  sakura: "🌸",
  sushi: "🍣",
  plane: "✈️",
};
Позже можно заменить это на:
const gameAssets = {
  puppy: "/sprites/puppy.webp",
  poop: "/sprites/poop.webp",
  ...
};
или на отдельные React-компоненты.
Замена ассетов не должна требовать изменения game state или game rules.

3. добавить animations;
4. улучшить audio;
5. добавить transitions;
6. улучшить сертификаты;
7. добавить декоративные эффекты.

Non-goals
Не нужны:
• backend;
• accounts;
• persistence;
• multiplayer;
• mobile gameplay;
• touch controls;
• game engine;
• advanced physics;
• procedural map;
• tile-map engine;

Сначала полностью пройти игру от НАЧАТЬ до финального выбора на emoji. Только потом рисовать красиво.
